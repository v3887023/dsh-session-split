# 会话分屏 / Session split view

把主区域变成多会话工作台：最多六格并排，每格都是**官方原版会话界面** —— 真正的聊天流、真正的输入框、原版的工具卡片、审批与提问卡片。

## 怎么用

1. 点击左侧栏的「会话分屏」图标进入工作台。
2. 放会话进来：
   - 左侧会话列表里**右键**某个对话 →「在分屏中打开」；
   - 或把左侧对话**拖进分屏区域**；
   - 或点工具栏「加入当前对话」。
3. 布局：
   - 默认自动：2 格左右、3 格三列、4 格田字、5–6 格 3×2；
   - 工具栏「列 / 自动 / 2 / 3 / 4」可以手动锁列数；
   - **拖动列之间的分隔条可以任意调整列宽**（每列最少 8%），比例会记住；**双击分隔条**恢复等分；
   - **拖动某一格的标题栏可以调整顺序**：拖到另一格上松手就占据那个位置，顺序会记住。
4. 每格右上角：↗ 在原生会话界面打开，✕ 移除；标题下方列出该会话的**子 Agent**，点一下在新格打开它。

## 为什么能做到原版效果

DSH 的会话界面（`conversation.content`）是注册在 slot 系统里的 Component Factory，而 slot 渲染器给了插件两件关键能力：

- `renderFactorySlot('conversation.content', …)`：任何 slot 组件都能按名字渲染这个工厂；
- `SessionProvider`：把工厂这一次渲染指到某个 `SessionReference`，而 `ctx.sessions.retain(id)` 可以为任意会话生成引用。

两者都会作为渲染工具包交给「声明过 session 作用域子槽位」的 slot 组件。每一格就是：retain 会话 → `SessionProvider` 包住官方工厂 → 渲染。**没有一处是重新实现的会话界面。**

官方工厂按官方嵌入实例的方式调用（`variant: 'embedded'` 加上按会话快照推导的 `phase`/`hero`），所以输入框吸底等布局规则由官方自己生效，插件不需要任何布局补丁。

## 为什么没有标题栏里的视图标签行和子 Agent 树

这两块属于官方会话页的外壳 `main.conversation`，是 slot 系统里的**单例**：插件如果去声明它，会顶掉官方声明，整页会话起不来（实测报 `slot "main.conversation" is already declared`）。

所以每格用的是自己的一行紧凑标题条（拖动柄、标题、状态、子 Agent chips、↗、✕），视图切换请用 ↗ 回原生页。

## 限制

- **同一个会话只出现一次**（官方文档明确：同一会话不支持两个可编辑根）。
- **最多六格**，满了再加会顶掉最早的一格。
- 进入分屏时原生会话列会卸载，这正好避免两处草稿与滚动位置互相打架。

## 与其它插件的分工

「拖动会话行」这个手势在会话页属于 `dsh-session-reference`（把对话引用进输入框）。为避免同一次拖放触发两个动作，本插件只在**分屏工作台内部**接管拖拽；从会话页进入请用右键菜单或工具栏按钮。
